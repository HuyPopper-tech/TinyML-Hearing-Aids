# TLV320DAC3100 I2S Headphone Transport

## Current custom binding — 2026-11-08

Custom product: I2S1 PA8 DO / PA10 MCLK / PA11 BCLK / PB0 LRCK, I2C0 PA4 SDA / PA5 SCL at400 kHz, address0x18; playback PDMA0 channel0. PF0/PF1 retain SWD. The product uses16 kHz/hop16, with two startup silence slots.

See [R2 integration](../r2_custom_integration.md) for current ownership/recovery and evidence limits.

## FIFO-aware product DMA ownership — 2026-11-08

Product startup preloads16 stereo-zero frames into FIFO, then arms one terminal
BASIC task for the second silence block. Following tasks are armed only after
foreground publication. The DMA source is released on FIFO transfer, not on
serial playback completion. `playback_slot` is the logical block identity;
`dac_completed_cycle` must not be used as physical audio latency.

Real TX FIFO underflow uses I2S1 IRQ and the existing board playback callback:
acknowledge/count/stop, then foreground full recovery. No formatting/DSP in IRQ.
The terminal-task handoff is now the sole product playback implementation.
The unused scatter/32-kHz path and untagged submit API were removed on2026-11-09.
See [verified scope and next run](../verification/2026-11-08-fifo-dma-handoff/README.md).

## Purpose and Boundary

`drivers/tlv320dac3100/` is the output transport/reference layer for one
TLV320DAC3100 headphone codec. It accepts signed-16 mono PCM from a caller,
duplicates it to stereo, and sends it through custom-board I2S1 and PDMA0. It owns codec
register programming, the I2S transmit stream, and PDMA descriptor ownership.
It does not capture DMIC data, resample, run TinyML, provide AGC/EQ, or make a
medical hearing-aid safety claim.

The only accepted profile is16 kHz,16 samples per1-ms hop, direct4.096 MHz
MCLK,512 kHz BCLK and16 kHz LRCK. Board APLL1/2 and I2S divider58 remain
unchanged. Invalid profile values and mismatched I2S/MCLK results are rejected.

## PCM, DMA, and software timing

`tlv320dac3100_submit_mono_block_tagged(samples,16,&tag)` requires a nonzero,
in-order capture sequence and timestamp. It copies caller-owned PCM before
returning. Two non-cacheable16-word stereo buffers and a silence buffer are
owned by the driver; descriptors are terminal BASIC tasks with NEXT0. The
StdDriver SCATTER *loader* selects one template; the template itself cannot
chain or prefetch a second task. Each32-bit FIFO word packs both signed16-bit
channels. IRQ exclusion, request gating, bounded busy/TD checks, barriers and
pre/post-copy underflow checks protect publication.

The board supplies two initial silence slots. Sequence1 maps to logical playback
slot2, with no added queue hop. TX TD releases the DMA source after FIFO transfer,
not after acoustic playback. Real FIFO starvation, aborts, sequence faults and
deadline failures stop/mute and require the service's full synchronized reset.
The IRQ never processes DSP, writes I2C or logs.

Ordinary Debug and Release continuously call the same service. Only the opt-in
Release Probe stops at60,000 hops to print timing after DMA stops. The supplied
run reached60,000 hops with max total863 us, capture-to-progress885 us and zero
fault counters; its flashed hash was not supplied. See the
[run receipt](../verification/2026-11-08-board-probe-60000/README.md) and
[finalization handoff](../verification/2026-11-09-continuous-product/README.md).
These software intervals are not microphone-to-headphone acoustic latency.

## Gain, Mute, and Recovery

The board defaults to `max_digital_gain_db=-9 dB`; CMake `M55M1_DAC_GAIN_DB`
selects startup volume and runtime ceiling in whole dB from -63 to 0. See
[audio gain configuration](../AUDIO_GAIN_CONFIGURATION.md). Earlier -12 dB
headphone and -3 dB bring-up settings are historical. The ceiling is not a
calibrated acoustic output limit. Digital attenuation reduces speech and noise already
present in PCM by the same amount; it does not improve their signal-to-noise
ratio or remove headphone-stage hiss.

`tlv320dac3100_set_channel_digital_gain_db(left, right)` supports independent
L/R attenuation from -63 dB through that ceiling. The legacy equal-gain API
maps to both channels. Do not bypass this policy through direct codec register
writes. DAC attenuation is downstream of input conditioning and model/FIR;
changing it does not change the samples received by the model.

Initialisation resets the codec, waits its 1 ms lockout, uses bounded I2C
ready/write retries, configures de-pop/routing, and powers HPL/HPR only after
the safe sequence. HPL/HPR register `0xC4` keeps short protection in
current-limit mode: a TRS plug can briefly short the right-ring contact during
insertion, and shutdown mode can latch the right channel off. `mute` changes
digital mute without stopping I2S; `stop` mutes, stops PDMA/I2S, and powers down
the analogue path. `recover` reruns init with the selected profile only after
an explicit caller decision.

## Historical NuMaker wiring (not the active custom product)

The following wiring is retained as historical bring-up evidence only. The current
custom product uses I2C0 PA4 SDA / PA5 SCL and I2S1 PA8/PA10/PA11/PB0. Do not infer
the custom codec RESET connection from this older setup. CH549 has no physical
nRESET connection. See [custom I2C recovery trace](../i2c_stuck_trace.md) for
`board_status=5` diagnostics and the remaining physical verification boundary.

In that historical setup, the Adafruit codec `RST` pin is connected to the NuMaker nRESET header net.
I2C1 uses PB1/PB0 at 400 kHz. Before I2C starts, the board sends up to nine
open-drain SCL recovery pulses and a STOP; this handles a codec that held SDA
after an MCU-only reset. A real hardware reset/power-cycle is still required
when the codec cannot ACK.

## Continuous-audio power policy — 2026-11-08

The product keeps direct MCLK/DOSR256/PRB_P7 and both headphone outputs. After
reset it explicitly writes PLL P0R5=0x11, headset detection P0R67=0, volume ADC
P0R116=0, Class-D P1R32=0x06 (reserved bits retained), MICBIAS P1R46=0. These match
reset off states; no additional codec current reduction has been measured.
Startup/retry/depop waits use `m55m1_timebase_delay_us` so external SysTick timing
survives recovery. Do not use vendor SysTick delay APIs on the active product
counter. No lineout mode, gain, depop or headphone load assumption was changed.
See [continuous power evidence](../continuous_low_power.md).

## Bounded I2C completion and Debug diagnosis — 2026-11-09

`codec_status=5` means a codec I2C operation failed; it differs from board
`I2C_STUCK=5`. Bus-free GPIO recovery is earlier than codec transactions.
The register writer now waits for hardware STOP completion before returning
success or issuing another START. SI/STOP polls and retries remain bounded.
Failure status/control and byte step are captured before abort, then copied
through the portable transport report to stopped Debug UART `[CODEC_I2C]`.
No logging was added to ordinary Release or the live audio path.
See [verification and retest instructions](../verification/2026-11-09-codec-i2c-init/).
The native STOP race was reproduced and corrected; the user's physical
intermittent failure still requires a revised-image retest.
