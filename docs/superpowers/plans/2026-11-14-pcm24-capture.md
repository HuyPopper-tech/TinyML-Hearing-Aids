# PCM24 capture implementation plan

Historical PCM24/+24 dB plan; implemented and tested before the current +12 dB hardware/+21 dB software trial. The original no-commit scope was superseded by the explicit granular-commit/push request. See [current verification](../../verification/2026-11-14-pipeline-cleanup.md).

**Goal:** Trial signed PCM24 capture at 16 kHz, DMIC +24 dB, DAC -9 dB.
**Architecture:** Board reads FIFO24 with DMA32 and sign-extends the low 24 bits.
Transport carries signed int32 samples. The service normalizes to float before
the existing shared frontend/FIR; the INT16 model and PCM16 playback stay intact.
**Spec:** User-approved short design in this chat (2026-11-14).
**Execution:** Light route, main agent only, current workspace including prior
authorized gain/statistics changes; no commit, flash, or unrelated cleanup.

## Acceptance and review focus

- Exactly 16 samples/hop at 16 kHz; preserve PA1 clock, PA2 data, channel 2,
  rising latch, OSR128/PDM 2.048 MHz, and PF0/PF1 SWD recovery.
- Decode both zero-filled and sign-filled upper bytes; validate PCM24 range.
- No PCM16 truncation on the production path before feature and FIR processing.
- Retain PCM16 replay API and explicit PCM16 diagnostic export conversion.
- Count PCM24 endpoint hits/peak in non-cacheable SWD statistics across restarts.
- Test PCM16*256 equivalence and retained low bits; preserve invalid-input,
  alias, reset, sequence, deadline and failure behavior.
- Host tests, Debug/Release builds, diff check, linker/GDB symbol checks.
- Physical alignment, audio quality and 1 ms deadline require a later board run.

## Execution evidence (2026-11-14)

- Debug and Release builds succeeded with Arm Compiler 6.24. Both product caches
  select gain24; UART capture and finite Release probe are OFF.
- Host suite: 141 tests passed in 36.592 seconds, with no skips. Coverage includes
  FIFO payload sign decoding, actual DMA descriptor/foreground-copy functions,
  PCM16*256 streaming equivalence in scalar and CMSIS FFT fixtures, sub-PCM16
  waveform retention, invalid-range/alias/failure/reset gates, native MVE lane
  normalization and linked non-cacheable statistics placement.
- Installed GCC helper programs could not locate their DLL dependencies. The
  plain unittest command failed for this environment reason. Validation copied
  existing cc1/cc1plus/as/ld/collect2 and installed DLLs into ignored
  `diagnostics/native-gcc-bin`; the temporary runner injects `-B` for GCC and
  places the three existing C++ runtime DLLs beside generated test executables.
  No installed toolchain files or test assertions were changed for this workaround.
  Command: `python -X utf8 diagnostics/run_host_tests_pcm24.py discover -s tests -v`.
  Full local log: `diagnostics/pcm24-host-tests.log` (ignored).
- Release disassembly verification passed for all nine required kernel ranges,
  including actual PCM24 vector conversion with fractional-bit immediate23.
- Offline GDB resolved typed `g_stats` at `0x20230180`, size88, in both AXFs.
  Both maps place the full object inside SRAM_NONCACHEABLE at
  `0x20230000..0x20250000`. GDB confirms capture int32[16], playback int16[16].
- `git diff --check` passed. Integration was reviewed locally on the Light route;
  existing user changes and untracked documents were preserved.
